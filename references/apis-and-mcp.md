# API, MCP и получение документов

API — структурированный доступ к конкретному сервису; MCP — способ предоставить инструменты агенту. Наличие документации или сервера в реестре не означает, что он подключён, авторизован или покрывает нужный архив. Этот навык описывает маршруты; сам не устанавливает серверы и не выдаёт ключи.

## Выбрать доступный инструмент

Сначала посмотреть реально доступные инструменты и их схемы. Использовать подключённый коннектор, официальный API или существующий скрипт проекта, если он решает задачу. Для каталога со сложной формой — доступный браузер. Не придумывать endpoint по похожему сайту и не называть внутренний сетевой запрос документированным API.

Прочитать действующую документацию владельца: авторизация, разрешённые операции, лимиты, пагинация, лицензия, сохранение/перераспространение. Пробный небольшой запрос должен вернуть нужный тип данных и устойчивый ID. Проверять `error`, `total`, `next/cursor`, фильтры и фактическое содержимое, а не один HTTP 200. Пустой промежуточный ответ/оболочка/ошибка загрузки не является нулём результатов.

## Документированные маршруты

|---|---|---|---|

| A02 | [NARA Catalog API v2](https://www.archives.gov/research/catalog/help/api-getting-started) | Описания, авторитетные записи, метаданные цифровых объектов и доступный текст | Нужен API key; использовать v2 по актуальной документации, не старые примеры v1 |
| A03 | [Library of Congress JSON/YAML](https://www.loc.gov/apis/json-and-yaml/) | Поиск, item/resource, газетные и иные цифровые объекты | Документирован `fo=json`; тестовый запрос из этого окружения вернул 403, не обещать доступность каждому клиенту |
| A04 | [Europeana APIs](https://api.europeana.eu/en) | Поиск цифрового наследия и метаданные записей/поставщиков | API key через Europeana account; старые страницы API могут перенаправлять. Право на объект определяется у поставщика |
| A05 | [IIIF Presentation 3](https://iiif.io/api/presentation/3.0/) | Manifest → canvas → страница/изображение/аннотация, структура многолистного дела | Стандарт, не единый архив и не поисковый индекс. Сначала получить настоящий manifest из каталога/просмотрщика |
| A06 | [IIIF Image 3](https://iiif.io/api/image/3.0/) | Размер, поворот и фрагмент изображения через опубликованный image service | `info.json`, поддерживаемые размеры и ограничения сервиса; не считать всякий viewer IIIF-совместимым |
| A07 | [MediaWiki Action API](https://www.mediawiki.org/wiki/API:Main_page), [Imageinfo](https://www.mediawiki.org/wiki/API:Imageinfo) | Wikisource/Commons: страница, ревизия, описание файла, оригинальный URL, размер, SHA-1/лицензия | Публичное чтение и лимиты конкретного wiki; авторство транскрипции не подменяет происхождение скана |
| A08 | [Wikidata SPARQL](https://www.wikidata.org/wiki/Wikidata:SPARQL_query_service) | Исторические топонимы, учреждения, идентификаторы, кандидаты по биографиям | Вторичный граф; ссылки утверждения проверять. Внешний ID не делает все поля записи достоверными |
| A09 | [Gallica Document API](https://api.bnf.fr/fr/api-document-de-gallica) | Метаданные и структура уже найденного документа BnF | Использовать настоящий ARK; поиск и выдача изображений — отдельные интерфейсы из документации BnF |
| A10 | [Internet Archive developer portal](https://archive.org/developers/) | Поиск изданий, item metadata, список доступных файлов | Публичный файл/borrow/ограниченный объект различаются; происхождение загрузки и условия учитывать |
| A11 | [Open Library Search API](https://openlibrary.org/dev/docs/api/search) | Найти издание, автора, варианты заглавий и ссылки на цифровую копию | Небольшой публичный запрос проверен: JSON с ID работы. Это библиография, не полный текст книги |
| A12 | [Open Archives API](https://www.openarchieven.nl/api/docs/) | Именной поиск, метаданные исторических записей и архивные ссылки | Опубликованы OpenAPI YAML/JSON, лимиты и официальный remote MCP; читать условия конкретного метода |
| A13 | [Crossref REST API](https://www.crossref.org/documentation/retrieve-metadata/rest-api/) | Профессиональная биография: публикации, DOI, авторы, библиография | Метаданные; не все исторические работы имеют DOI, инициалы не устанавливают личность |
| A14 | [OpenAlex API](https://help.openalex.org/api/), [авторизация](https://help.openalex.org/api/authentication/) | Публикации, авторы, учреждения и ссылки на тексты | Актуальная страница разрешает базовые запросы без ключа; расширенная работа/пагинация требуют ключа. Проверять лимиты и стоимость перед масштабированием |
| A15 | [EPO Open Patent Services](https://www.epo.org/en/searching-for-patents/data/web-services/ops) | Патентные библиографические данные и документы для биографии изобретателя | Регистрация приложения и OAuth; заявка, публикация, выдача и спор — разные события |
| A16 | [Official MCP Registry](https://registry.modelcontextprotocol.io/docs) | Найти актуальное описание MCP, transport, пакет/репозиторий и версии | Это каталог серверов, не гарантия безопасности или доступа. OpenAPI доступна; схему брать оттуда, не из старого примера |

Для NARA дополнительно читать [условия API](https://www.archives.gov/research/catalog/help/api): опубликованы ограничения запросов, массового скачивания и кэширования/хранения API-контента. Не применять к нему общий совет «сохранить весь JSON» автоматически. Для массового набора существует отдельный официальный dataset; персональное исследование не повод выгружать весь каталог.

## MCP, подтверждённые документацией владельца

| Сервер | Подтверждённый маршрут | Как использовать |
|---|---|---|
| Open Archives | `https://mcp.openarchieven.nl/` — опубликован в [документации самого Open Archives](https://www.openarchieven.nl/api/docs/) | Проверены initialize, 22 инструмента и поисковый вызов. В версии сервера 1.1.1 `get_births` вернул записи вне переданного `eventyear`; такой ответ нельзя считать поиском только заданного года |
| OpenAlex | `https://mcp.openalex.org/mcp` — опубликован в [инструкции OpenAlex для AI-инструментов](https://help.openalex.org/how-to/ai-assistants/) | Научная/профессиональная библиография; вход и поддержка клиента по текущей документации. Не считать все инструменты сервера только чтением |

Подключённый в рабочей среде MCP использовать по его фактическим возможностям. Не считать сервер с названием `genealogy` официальным FamilySearch/архивным API. Новое подключение выбирать по реальному пробелу: владелец и репозиторий, читаемые операции, авторизация, передаваемые данные, обслуживание. Установка пакета, OAuth и расширение разрешений — отдельные действия в пределах поручения. Запись в дерево, отправка сообщений, платный вызов и загрузка семейных файлов не следуют из доступности метода.

Наблюдавшийся сбой фильтра показывает границу проверки: даже успешный вызов с подходящей схемой может выполнить более широкий запрос. Сопоставлять возвращённые даты/места с фильтрами и, где есть, отражёнными параметрами `query`. Если фильтр проигнорирован, сохранить исходный ответ как широкий поиск, проверить документированный API/другой метод или обработать весь подходящий результат в явном объёме; не делать отрицательного вывода по первой странице.

Полезные роли существующих коннекторов:

- **Поиск и браузер:** открытые каталоги, газетные и локальные сайты, формы поиска. Не заменять источники ответом поискового AI.
- **Файлы и семейные облачные архивы:** найти уже предоставленные книги, документы, дерево, переписку. Не сканировать несвязанные личные хранилища «на всякий случай».
- **PDF, OCR/HTR и транскрипция:** извлечь текст/страницы/таймкоды, сохранить неуверенное чтение и сверить со сканом. Не загружать приватные оригиналы во внешний OCR без соответствующего поручения.
- **Таблицы и база проекта:** реестр людей, утверждений, источников и выполненных запросов; обновлять существующий формат, не вводить базу данных ради небольшой семьи.
- **Telegram и другие каналы выдачи:** отправить разрешённую пользователем находку, прочитать её обратно и сохранить квитанцию; не обращаться к родственникам самостоятельно.

## Получение и проверка оригинала

1. Сохранить постоянную ссылку карточки, хранителя и шифр. Временный signed URL/токен не публиковать и не считать постоянной ссылкой.
2. В IIIF/JSON найти конкретный canvas/объект и опубликованное изображение. Сверить порядок страниц, подписи и полный размер. Номер PDF-страницы, кадра, печатной страницы и архивного листа хранить раздельно.
3. Скачивать только нужные документы в разрешённых пределах; корректно обрабатывать пагинацию и `Retry-After`. При 401/403/429/CAPTCHA/платном доступе записать ограничение и продолжить другие доступные источники. Не перебирать скрытые URL и не снимать защиту.
4. Проверить статус, MIME, сигнатуру, ненулевой размер и открытие файла: HTML с ошибкой не PDF/JPG. Сохранить SHA-256, время доступа, ссылку и происхождение, если это допускают условия источника.
5. Оригинал оставить неизменным. Производные страницы, повороты и фрагменты обозначить как производные с указанием источника. Не «восстанавливать» буквы генеративной дорисовкой; OCR и транскрипция отдельными файлами.
6. Сверить саму запись и соседний контекст. Успешный API-вызов, download или OCR не доказывает найденного родственника.

## Доставка находок по поручению

Пользователь может заранее разрешить отправлять все новые находки в конкретный канал. Сохранить это разрешение, адресата, язык и формат в проекте; не спрашивать повторно для каждой находки в согласованных границах.

Если нужны отдельные изображения: **один скан → одно сообщение с подписью**. Подпись: кто/что, где смотреть (кадр/лист/строка), буквальное содержание, что это подтверждает и что ещё неизвестно, постоянная ссылка. Полный документ/отчёт можно приложить дополнительно. Обложку или начало раздела не подписывать как именную запись или датированный указ.

Для нового сайта: ссылка, что в нём искать, география/тип документов, фактически проверенное и доступ. Если найден только каталог, не называть его новой персональной находкой. Вести журнал `источник/файл+SHA-256 → подпись → ID сообщения → прочитанное подтверждение`. Перед повторной отправкой проверить журнал; после неоднозначной ошибки проверить историю, а не создавать дубликат. Соблюдать действующий skill коннектора и правила подписи AI; Saved Messages и другие исключения определяются правилами среды.
